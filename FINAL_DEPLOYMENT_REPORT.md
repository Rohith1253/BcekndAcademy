## 4. 🛠️ Step-by-Step Production Launch Instructions

### Step 1: Push Local Git Commits
```bash
git push origin main
```

### Step 2: Deploy Backend to Render
1. Open [Render Dashboard](https://dashboard.render.com).
2. Click **New +** -> **Web Service** -> Connect repository `Rohith1253/BcekndAcademy`.
3. Render automatically detects [`render.yaml`](./render.yaml) at root.
4. Set Environment Variables in Render Dashboard:
   - `MONGODB_URI`: Your MongoDB Atlas connection URI
   - `CLIENT_URL`: `https://your-frontend-domain.vercel.app`
   - `FRONTEND_URL`: `https://your-frontend-domain.vercel.app`
   - `JWT_SECRET`: (Auto-generated by Render or enter custom 32+ char secret)
5. Click **Deploy Web Service**.
6. Copy your public Render URL: `https://<your-service-name>.onrender.com`.

### Step 3: Deploy Frontend to Vercel
1. Open [Vercel Dashboard](https://vercel.com/new).
2. Import repository `Rohith1253/BcekndAcademy`.
3. In **Project Settings**:
   - **Root Directory:** `frontend`
   - **Framework Preset:** Next.js
4. In **Environment Variables**:
   - Add `NEXT_PUBLIC_API_URL` = `https://<your-service-name>.onrender.com/api`
5. Click **Deploy**.

### Step 4: Final CORS Handshake
1. Return to your Render Web Service settings.
2. Ensure `CLIENT_URL` and `FRONTEND_URL` match your exact assigned Vercel URL.
3. Verify `/health` on Render and open your live Vercel frontend.

## 7. ⚠️ Known Limitations & Operational Considerations

1. **Render Free Tier Spin-Down:**
   - On Render free instances, the service spins down after 15 minutes of inactivity. Initial requests after spin-down may take ~30-50s to cold start. (Upgrading to Starter plan provides zero cold starts).
2. **Pluggable Sandboxing:**
   - The default `CODE_EXECUTION_PROVIDER=mock` executes safely in simulation mode without requiring container privileges. Setting `CODE_EXECUTION_PROVIDER=piston` connects to a dedicated Piston container cluster if desired.
